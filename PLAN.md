# Capture + — personal macOS capture utility (plan)

Personal menu-bar app for joh. Three features: screen recording (system audio + optional mic),
region screenshots straight to clipboard, short-lived clipboard history. Runs on two personal
Macs (Apple Silicon). Not distributed. Researched 2026-07-17 (macOS 26 Tahoe, Xcode 26.6).

## Ground rules
- Swift 6 + SwiftUI, single menu-bar app (`LSUIElement`), no Dock icon.
- **Minimum macOS 15.0** (required by the recording API below). Verify the second Mac is on 15+.
- Free personal-team signing; build in Xcode, copy the .app to the other Mac (or clone + build).
- Keep it a git repo from day one for the two-Mac sync.
- License hygiene when borrowing code: **Maccy (MIT)** and **BetterCapture (MIT)** are safe to
  copy patterns/code from. **QuickRecorder is AGPL** — read for ideas only, don't copy code.
  **Azayaka has no license** — read-only.

## Feature 1 — Screen recording
- API: ScreenCaptureKit `SCStream` + **`SCRecordingOutput`** (macOS 15+). It writes screen +
  system audio + mic to ONE file itself — no AVAssetWriter, no BlackHole, no audio-device
  toggling. Config: `SCStreamConfiguration.capturesAudio = true`, `captureMicrophone` per user
  toggle (needs `NSMicrophoneUsageDescription`).
- Codec: HEVC (`videoCodecType = .hevc`), `.mp4`. SCRecordingOutput doesn't expose bitrate;
  its automatic rate control is fine. Only if files come out too big, fall back to the manual
  AVAssetWriter path with `AVVideoAverageBitRateKey` (~4–6 Mbps 1440p, ~8–12 Mbps 4K/5K).
  Warning for that fallback: mic + system audio arrive as separate buffer streams with
  independent clocks — separate writer inputs + timestamp offsetting or the file corrupts
  (Apple DTS thread 805892).
- Flow: menu-bar button / hotkey → record full display (v1: whole screen only) → stop →
  trimmer sheet → save.
- Known cost: apps that record without the system picker get a **~monthly TCC re-approval
  prompt** (Sequoia/Tahoe behavior). QuickRecorder etc. just accept it; we do too.
  (Alternative, `SCContentSharingPicker`, avoids the nag but forces the clunky system picker
  each time — rejected for UX.)

## Feature 2 — Post-record trimmer
- `AVPlayerView` (AVKit) has the built-in QuickTime-style trim UI: `canBeginTrimming` /
  `beginTrimming(completionHandler:)`. Present it in a window right after recording stops.
- Export trimmed range with `AVAssetExportSession`, **`AVAssetExportPresetPassthrough`** +
  `timeRange` → lossless and near-instant (no re-encode). Use the modern async
  `export(to:as:)` API (old callback API deprecated in macOS 15).
- Caveat (acceptable): passthrough cuts snap to nearest keyframe, so trim points can shift by
  ~1–2 s. Fine for "chop the dead start/end".
- "Skip trim" button saves immediately.

## Feature 3 — Saving & organizing
- Recordings → `~/Movies/Capture +/YYYY-MM/Recording YYYY-MM-DD at HH.mm.ss.mp4`.
- After save: notification with "Reveal in Finder"; optionally copy file to clipboard.
- No desktop littering, ever.

## Feature 4 — Region screenshots
- Hotkey → shell out to `/usr/sbin/screencapture -i -c` → system crosshair/region picker →
  image lands ON THE CLIPBOARD, nothing written to disk. This is exactly the pain fix:
  no thumbnail race, no desktop files.
- Space bar during selection = window capture, free (system UI).
- Also ingest the captured image into the clipboard-history panel so a "recent shots" row
  exists if a screenshot gets clobbered by the next copy.
- (Rejected: SCScreenshotManager + custom overlay picker — a week of UI work for no gain.)

## Feature 5 — Clipboard history (short-lived)
- Poll `NSPasteboard.general.changeCount` every ~0.5 s (still the only mechanism; Maccy does
  the same — borrow their `Clipboard.swift` pattern, MIT).
- Skip sensitive items: any item whose types include `org.nspasteboard.ConcealedType`,
  `TransientType`, or `AutoGeneratedType` (password managers set these).
- **Retention: default 5 hours, max 24 h, purge timer + purge-on-launch.** In-memory store
  with optional lightweight on-disk cache (encrypted or plain file in App Support — decide at
  build; in-memory only is simplest and most private, loses history on quit, which is
  acceptable for a 5 h window).
- Cap item count (~200) and per-item size (skip >10 MB blobs) so memory stays trivial.
- History panel: hotkey → small SwiftUI popup, click/enter re-copies item.
- **Tahoe pasteboard privacy alerts**: macOS 26 warns when apps read the clipboard
  programmatically. Onboarding must walk the user through setting Capture + to "Always Allow"
  in System Settings (one-time per Mac). Use `NSPasteboard.accessBehavior` to detect and
  show guidance. Note: Tahoe's own Spotlight clipboard history (8 h) exists but doesn't
  cover images-from-screencapture flow + our UX; still worth building.

## Permissions checklist (onboarding screen, per Mac)
1. Screen Recording (TCC) — needed for recording; also covers screenshots.
2. Microphone — only when mic toggle first used.
3. Pasteboard "Always Allow" — for clipboard history (Tahoe).
4. Login item — so clipboard capture is always on.

## Build order (each step independently shippable)
1. Menu-bar shell + global hotkeys (use `KeyboardShortcuts` SPM package) + screenshot hotkey
   (`screencapture -i -c`). ~Smallest win first.
2. Clipboard history (poll, skip-list, 5 h purge, popup panel) + Tahoe onboarding.
3. Recording: SCStream + SCRecordingOutput, HEVC, system audio, mic toggle.
4. Trimmer sheet (AVPlayerView + passthrough export) + save/organize + notification.
5. Polish: settings window (retention hours, save folder, hotkeys), login item, app icon.
