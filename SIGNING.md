# Signing & building Capture +

Capture + is signed with a **local self-signed certificate**, not an Apple one. This
is deliberate: a stable signature is what makes macOS remember your Screen
Recording / Microphone grants across rebuilds. An unsigned ("adhoc") build gets
a new identity every rebuild, so macOS keeps re-asking for permission — that's
the bug this setup fixes.

The certificate is only meaningful on your own Mac. It does **not** help
distribute the app to other people — a friend opening a `.dmg` still hits
Gatekeeper. Sharing without warnings needs the paid Apple Developer Program
($99/yr) + notarization, which is a separate step.

## First time on a Mac

```sh
brew install xcodegen          # if not already installed
./scripts/setup-signing.sh     # creates the local signing cert (once per Mac)
./scripts/build.sh             # build + sign + install to /Applications
```

Then launch Capture + and grant **Screen Recording** once. It sticks from then on.

## Rebuilding after code changes

```sh
./scripts/build.sh
```

Or open `Capture +.xcodeproj` in Xcode and press ⌘R — the project is configured for
manual signing with the same cert, so Xcode builds are signed correctly too.

## Notes

- The cert lives in a dedicated keychain `~/Library/Keychains/capture-plus-signing.keychain-db`
  (password `capture-plus-local`, local-only). Remove with `security delete-keychain`.
- `project.yml` hard-codes that keychain path under the `joh` home directory. If
  your other Mac uses a different username, update `OTHER_CODE_SIGN_FLAGS` there.
- `Capture +.xcodeproj` is generated by XcodeGen and git-ignored — `build.sh`
  regenerates it. Edit `project.yml`, never the `.xcodeproj` directly.
- Each Mac gets its own cert, so you grant Screen Recording once per Mac. Normal.
